# CodeCanvas: 5-Minute Student Classroom Pitch Storyboard

This document contains a slide-by-slide storyboard and word-for-word presenter script designed for a **5-minute classroom pitch** to get engineering students to register and sign up for CodeCanvas.

---

## Slide 1: Why Coding Labs Feel Like a Nightmare

* **Visual Layout**: Bold, high-energy slide. A screenshot of a frustrating compiler error message next to a cartoon showing a student staring blankly at a screen. Large text: **"Why Does Coding in Labs Feel So Hard?"**.
* **Slide Copy**:
  * **The Friction**: You write syntactically correct code, but it returns the wrong output.
  * **The Debugging Trap**: Standard GDB terminals and online compilers print dry text errors.
  * **The Stretched Professor**: One instructor cannot guide 60+ students at once.
* **Speaker Script (0:00 - 1:00)**:
  > "Hey everyone! Let's be honest for a second. How many of you have sat in a programming lab, written code that you *thought* was 100% correct, only for it to return a completely wrong output? Or worse, you get a 'Segmentation Fault' or 'Index Out of Range' and have absolutely no idea which line actually broke? You raise your hand, but the lab teacher is already surrounded by 15 other students. You end up wasting half the lab session waiting for help, or coding late at night with zero support. That is the coding lab gap, and today, we're changing that."

---

## Slide 2: The Core Problem — Invisible Memory

* **Visual Layout**: Infographic illustrating abstract structures (pointers, stacks, tree nodes) as invisible boxes inside a computer box, showing that students are coding blind.
* **Slide Copy**:
  * **Abstract concepts**: Pointers, linked list re-linking, recursion stacks, and sorting arrays are taught statically on blackboards.
  * **Coding Blind**: Standard IDEs compile code natively but keep memory scopes invisible.
  * **Logical Bugs**: Without visual state tracking, debugging logic errors is a guessing game.
* **Speaker Script (1:00 - 2:00)**:
  > "The reason programming feels so intimidating when you start is that computer memory is invisible. When a professor explains pointers referencing memory, nodes swapping in a linked list, or stacks popping in a recursion loop, they write it statically on a blackboard. But when you sit in front of VS Code, you can't see the memory stack. You are essentially coding blind. You compile, it fails, and you guess. What if you could actually see your variables mutating, your arrays sorting, and your linked lists linking, step-by-step in real-time?"

---

## Slide 3: The Solution — CodeCanvas (LPU CodeViz)

* **Visual Layout**: Clean slide showcasing the CodeCanvas IDE Sandbox. Left: Monaco code editor. Center: Animated data structures canvas (arrays, stacks, trees). Right: Contextual AI Tutor sidebar.
* **Slide Copy**:
  * **Interactive Visual Debugger**: Write code and step through live animations of your data structures.
  * **10 Visualizer Canvases**: Supports Stacks, Queues, Arrays, Sorting, Recursion, Trees, Graphs, SQL tables.
  * **Empathetic AI Tutor Sidebar**: Context-aware coding companion explaining bugs line-by-line.
* **Speaker Script (2:00 - 3:00)**:
  > "This is CodeCanvas, also known as LPU CodeViz. It's a web-based coding environment built specifically for us. You write your C, C++, Python, or SQL code in a built-in editor, click 'Visualize', and the system generates a step-by-step animated playback of your program. You can watch your array bars swap during Bubble Sort, watch your recursion call stack grow and shrink, and see variable scopes update instantly. Plus, there's a built-in AI Tutor sidebar that acts like a personal teacher, checking your specific code and guiding you to fix bugs without giving away answers."
